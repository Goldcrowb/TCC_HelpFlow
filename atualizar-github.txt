ATUALIZAR O HELPFLOW NO GITHUB — VERSÃO 2.2
=============================================

1. Faça backup do projeto e do banco Supabase. No GitHub Desktop, clique em Pull origin antes de começar.
2. Abra a pasta local do repositório (a que contém a pasta oculta .git).
3. Copie para ela TODOS os arquivos que estão DENTRO da pasta TCC_HelpFlow-main deste ZIP.
   Não exclua a pasta .git nem substitua arquivos .env com suas credenciais.
4. IMPORTANTE: copiar arquivos novos NÃO APAGA os antigos que já estão no GitHub.
   Remova manualmente do repositório os arquivos antigos listados abaixo, se existirem.
   Faça isso apenas após confirmar que a versão final do PDF, dos slides e do código foi copiada.

   - SHA256SUMS.txt (lista antiga estava desatualizada)
   - PASSO_A_PASSO_COMMIT_E_RENDER.txt (orientava a atualização da versão 2.1)
   - TESTAR-E-COMPILAR.bat (substituído por testar-projeto.bat)
   - tsconfig.core.json (não utilizado pela configuração atual)
   - apresentacao/Apresentacao_HelpFlow_TCC.pptx (apresentação antiga)
   - docs/01_...md até docs/12_...md (documentos preliminares)
   - docs/Documento_de_Arquitetura_HelpFlow_v2.docx e _v2_1.docx
   - referências repetidas das Fases 4 e 5 com acentos ou nomes #U00...

   MANTENHA os documentos finais docs/HelpFlow_EntregaFinal_v2.2.pdf e .docx,
   docs/evidencias/, docs/diagramas/, o documento de arquitetura original
   em referencias/, os scripts SQL, a apresentação final e todo o código em src/.

5. Confira a migração SQL no manual e só execute database.sql no Supabase com backup prévio.
6. No GitHub Desktop, confira exclusões e substituições antes do commit.
   Mensagem sugerida: Organiza entrega final e remove documentos duplicados
7. Clique em Push origin. Confira o deploy no Render e teste login, chamados,
   atendimento, transferência e administração com contas fictícias.
8. Antes da defesa, confira docs/pendencias.md e registre os testes externos de verdade.

A entrega final exige o PDF D1–D9, código-fonte e evidências. O ZIP contém o
código para instalar com Node/npm; não é um executável independente.
NUNCA envie .env, senhas, chaves ou credenciais do Supabase ao GitHub.
